The capstone

One command that turns the work-order export into a report Mazen can trust

  • In: 505 work orders (CSV) and the crews (JSON Lines), with planted problems
  • Rules: eight reasons to reject a row, applied in a fixed order
  • Out: a report for a person, a summary for a program, a rejection log
  • Always: accepted plus rejected equals the rows; two runs, the same bytes; nothing from the notes in any output
python -m workorders report \
  --orders data/work_orders.csv \
  --crews data/crews.jsonl \
  --as-of 2026-10-31 --out out

The brief is labs/capstone/README.md and was handed out at the end of Day 4. Every part of it was practised: the rules are Day 1 and Day 3, the aggregation Day 2, the command line and the same-bytes property Day 4. Any assistant is allowed for the building.

How the repository is scored

The rubric

20%

15%

The hidden tests run your command on files you have not seen. Other rows, the same rules. The public sample shows their shape.

Full marks, one example each. Hidden tests: every count of the summary right on the assessor's file. Validation: one reason per bad row, specific exceptions, exit code 2 for a missing file. Structure: loading, rules and reporting in separate modules, a clean strict type check. Reproducibility: a fresh clone, one command, the same bytes twice. README: the command, the report, and what the tool does not check.

The walkthrough · no assistant

10 minutes each, questions included

1 · Run it

From a fresh clone: the one command, then the report. About three minutes.

2 · Change it

The assessor asks for one small change. You make it live, with a test. About four minutes.

3 · Read a traceback

Produced from your code, chosen by the assessor. From the last line up: what, where, what you would check first.

While you wait. Read a neighbour's README and run their command. Write one thing that is clear and one question.

The walkthrough is twenty per cent of the assessment and shows whose understanding the repository is. Requested changes that fit four minutes: a ninth reason, another overdue threshold, a column in the report. For the traceback, run their tool on a file with a broken header or a crews file with a missing key and keep the output.
